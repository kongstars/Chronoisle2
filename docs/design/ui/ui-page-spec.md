## 1. 文档目标

本文档用于把 Chronoisle 主端后续的 UI 改造范围讲清楚，避免后续出现以下问题：

- 页面结构和服务能力不匹配，导致设计稿无法落地。
- 同一类 AI 能力在不同页面上交互方式不一致。
- 设计只覆盖成功态，没有覆盖配额、失败、同步、回退、加载中的状态。
- 测试只能按页面验收，无法按业务链路验收。

本文档默认采用的产品定位是：

- 不是“一个带 AI 的待办工具”
- 而是“一个围绕今天执行目标运转的个人执行系统”

## 2. 设计范围

本轮主端 UI 改造优先覆盖以下能力：

- 今日计划
- 一键重排
- 目标规划
- 语音创建
- 公告系统
- 会员、配额、积分流水
- 同步与埋点可观测性
- 深色/浅色双模式适配

本轮不展开后台 Web 的 UI 设计。

## 3. 产品信息架构

### 3.1 一级导航

建议目标架构采用 `Today / Goals / Calendar / Me + Global Create`。

说明：

- `Today` 是唯一首页，承担“今天做什么、为什么做、现在先做什么”。
- `Goals` 负责目标库、目标详情、AI 拆解、目标复盘。
- `Calendar` 负责提醒、倒计时、计划落点，不再承担第二个任务首页职责。
- `Me` 负责账号、会员、积分、配额、主题、帮助。
- `Global Create` 负责文字创建、语音创建、AI 补全。

## 4. 全局设计原则

### 4.1 首页原则

- 首页只能有一个最强视觉焦点：`今日计划 Hero`。
- 任何新功能如果与“今天的执行”强相关，优先挂在 `Today`。
- 同步、公告、会员不足、配额不足等系统状态，必须在首页有反馈，不允许用户进入深页面后才发现问题。

### 4.2 AI 原则

所有 AI 功能必须遵守同一套交互合同：

1. 触发前校验：登录、会员、配额、网络。
2. 生成中说明：告诉用户正在做什么、预计多久、当前是哪一步。
3. 结果预览：不是只给结论，要说明“为什么这样建议”。
4. 采纳与编辑：允许直接采纳，也允许局部编辑后采纳。
5. 失败兜底：明确区分网络失败、服务降级、配额不足、本地模板回退。
6. 可追溯：至少要能看到本次生成发生了什么。

### 4.3 系统状态原则

以下状态必须视为一等公民：

- `loading`
- `empty`
- `error`
- `syncing`
- `quota_locked`
- `membership_required`
- `ai_generating`
- `ai_preview`
- `adopted`
- `degraded_to_local`
- `offline`

### 4.4 视觉原则

- 风格关键词：`冷静、可信、轻智能、执行感`
- 页面靠留白、体块和信息层级建立秩序，不依赖大面积装饰。
- 蓝色仅表示主动作和系统建议。
- 会员权益使用独立金色体系，不与主系统蓝混用。
- 风险和逾期统一使用橙红体系。

### 4.5 深浅色模式适配原则

- 深色模式和浅色模式都属于正式交付范围，任何一个都不能视为“后补适配”。
- 所有核心页面、核心组件、关键状态都必须同时给出浅色和深色设计稿。
- 深色模式不是简单颜色反相，必须重新校准以下语义层级：
  - `background`
  - `surface`
  - `surfaceElevated`
  - `textPrimary / textSecondary / textMuted`
  - `border / divider`
  - `primary / success / warning / danger / premium`
- 图标在两种模式下都必须保证：
  - 激活态和未激活态清晰可区分
  - 线性图标轮廓不发虚
  - 小尺寸下不会因为对比不足而消失
- 阴影、描边、分隔线、磨砂、模糊等效果必须单独按模式校准，不能直接复用同一组透明度。
- Today Hero、会员卡、风险卡、公告 Banner 这类重点模块，必须在深色模式下重新检查主次层级，避免“整屏一样亮”或“整屏一样灰”。
- 设计稿标注时要明确哪些颜色来自语义 token，哪些是一次性业务色，禁止页面级自由发挥。

## 6. 页面详细说明

### 6.1 P01 Today 首页

#### 业务目标

- 让用户 5 秒内知道今天最重要的事情是什么。
- 把“计划、风险、执行、提醒”放在同一屏完成。
- 承接公告、同步、会员/配额异常等系统状态。

#### 信息层级

1. 页面头部：问候语、搜索、入口状态
2. 公告与系统状态：公告、同步、积分、会员
3. 今日计划 Hero：今天最应该做的 1 到 3 件事
4. 风险区：逾期、冲突、重排建议
5. 执行区：聚焦任务列表
6. 时间区：倒计时、今日提醒
7. FAB：全局创建

#### 低保真线框

```text
+--------------------------------------------------+
| 早上好，用户名                           搜索/AI |
| [公告 Banner：今晚 22:00 发布新版本]             |
| [同步成功 10:25] [积分 1280] [会员有效至 05-12]  |
|                                                  |
| ┌──────────────────────────────────────────────┐ |
| | 今日计划                                      | |
| | 今天 3 个重点任务，预计 4.5 小时               | |
| | 1. 完成课程大纲                               | |
| | 2. 提交项目日报                               | |
| | 3. 晚间跑步 30 分钟                           | |
| | [查看计划] [重新生成] [手动调整]              | |
| └──────────────────────────────────────────────┘ |
|                                                  |
| ┌──────────────────────────────────────────────┐ |
| | 风险与重排                                   | |
| | 2 个逾期任务 · 1 个时间冲突                  | |
| | AI 建议：把“日报”前移到 14:00 前             | |
| | [查看建议] [一键采纳]                        | |
| └──────────────────────────────────────────────┘ |
|                                                  |
| 重点执行                                         |
| [任务卡 1]                                       |
| [任务卡 2]                                       |
| [任务卡 3]                                       |
|                                                  |
| 倒计时                                           |
| [倒计时卡 1]                                     |
|                                                  |
| 今日提醒                                         |
| [提醒卡 1] [提醒卡 2] [提醒卡 3]                |
|                                             FAB  |
+--------------------------------------------------+
```

#### 关键交互

- 点击 `查看计划`：进入今日计划详情面板，支持采纳、编辑、补充任务。
- 点击 `重新生成`：先进行登录、配额、网络校验，再进入 AI 生成中面板。
- 点击 `查看建议`：打开一键重排预览面板。
- 点击任务卡：进入任务详情。
- 点击同步状态：进入 Me 中的同步模块。
- 点击公告：打开公告详情或跳转外链。

#### Today 页面状态表

| 状态 | 触发条件 | 页面表现 | 用户动作 |
| --- | --- | --- | --- |
| 初次加载 | 进入首页 | 骨架屏，保留顶部和 FAB | 等待 |
| 无计划 | 今日没有本地/云端计划 | Hero 显示“今天还没有生成计划” | 生成或手动调整 |
| 有预生成计划未采纳 | 服务端 `/api/plan/today` 返回 pending | Hero 显示“AI 为你准备了建议” | 预览与采纳 |
| 已采纳计划 | 本地或云端有 adopted 数据 | Hero 显示采纳时间和任务摘要 | 查看详情 |
| 配额不足 | 今日计划额度不足 | Hero 按钮变为“查看权益” | 去会员页 |
| 风险为空 | 没有逾期和冲突 | 风险区折叠为一句积极提示 | 无 |
| 公告为空 | 无活动公告 | 公告区不占位 | 无 |
| 同步中 | 应用前后台自动同步 | 顶部状态条显示 `同步中...` | 可等待 |
| 同步失败 | 上传/拉取失败 | 顶部状态条显示失败说明和重试按钮 | 重试或稍后处理 |
| 离线 | 网络不可用 | 首页显示“当前为离线视图” | 浏览本地数据 |

#### 设计验收点

- 用户无需进入二级页面，就能看到今日计划、风险和提醒。
- 即使所有模块都为空，首页仍然不显得空洞。
- 顶部状态条不抢 Hero 的视觉焦点。
- 暗色模式下风险色、会员色、主按钮仍能明显区分。
- 图标、标签、边框、底栏在深色模式下不能塌成一个灰层。

### 6.2 P02 今日计划面板

#### 业务目标

- 呈现 AI 计划内容和采纳结果。
- 让用户知道计划来源于哪些任务，以及推迟了什么。
- 支持从计划页继续补充任务。

#### 推荐形态

- 首页 Hero 概览
- 点击后进入 `今日计划详情页` 或 `底部全屏 Sheet`

#### 低保真线框

```text
+--------------------------------------+
| < 今日计划                    更多    |
| 更新于 2026-04-19 09:10              |
|                                      |
| 计划摘要                             |
| 今天适合先完成两个高优先级任务，     |
| 下午处理低脑力事项，晚上留给运动。   |
|                                      |
| 聚焦任务                             |
| [任务 1 卡片：原因 + 预计时长]       |
| [任务 2 卡片：原因 + 预计时长]       |
| [任务 3 卡片：原因 + 预计时长]       |
|                                      |
| 延后任务                             |
| [任务 4 卡片：延后原因]              |
|                                      |
| [继续补充任务] [采纳并返回首页]      |
+--------------------------------------+
```

#### 状态表

| 状态 | 页面表现 |
| --- | --- |
| 无计划 | 空状态说明 + `生成今日计划` + `手动选择任务` |
| 生成中 | 分步骤进度卡：读取任务、生成建议、整理输出 |
| 预览态 | 展示聚焦任务、延后任务、摘要和理由 |
| 已采纳 | 顶部显示 `已采纳`，按钮改为 `编辑今天计划` |
| 失败态 | 展示具体失败类型，不只写“生成失败” |

#### 测试重点

- 已采纳状态与首页 Hero 一致。
- 从今日计划继续补充任务后，首页和任务数据同步刷新。
- 本地计划和云端计划冲突时，有明确优先级与提示。

### 6.3 P03 一键重排面板

#### 业务目标

- 让用户看懂 AI 调整了什么，而不是无感替换。
- 优先解决逾期任务、时间冲突、今天过载。

#### 低保真线框

```text
+--------------------------------------+
| < 一键重排                    说明    |
| 发现 2 个逾期任务，1 个时间冲突      |
|                                      |
| AI 建议                              |
| 1. 将“日报”从晚上改到下午 14:00      |
| 2. 将“复习英语”延后到明天上午         |
| 3. 把“跑步”保留到今晚                 |
|                                      |
| 变化预览                             |
| 原计划 -> 新计划                     |
| [差异卡 1]                           |
| [差异卡 2]                           |
|                                      |
| [编辑后采纳] [一键采纳]              |
+--------------------------------------+
```

#### 状态表

| 状态 | 页面表现 |
| --- | --- |
| 无风险 | 只显示一句“今天安排良好，无需重排” |
| 生成中 | 阶段进度：分析风险、重排任务、生成预览 |
| 可采纳 | 显示前后差异、每项变更原因 |
| 局部冲突未解决 | 标记剩余冲突，允许用户手动处理 |
| 配额不足 | 展示权益说明和去会员页按钮 |

#### 设计注意事项

- 不允许只给新结果，不给差异。
- 不允许把高风险任务直接隐藏到“明天”而不解释。
- 用户如果拒绝采纳，不应影响当前本地数据。

### 6.4 P04 Goals Hub

#### 业务目标

- 替代当前仅按过滤展示的任务列表。
- 体现“目标驱动行动”，而不是无上下文地堆任务。

#### 信息结构

- 顶部搜索
- 分段切换：`目标` / `行动`
- 目标列表：目标进度、最近里程碑、今天相关任务数
- 行动列表：任务、筛选、逾期、重要

#### 低保真线框

```text
+--------------------------------------------------+
| 我的目标与行动                             搜索  |
| [目标] [行动]                                   |
|                                                  |
| 目标列表                                         |
| [目标卡：考研上岸 72% / 今日 2 个行动]          |
| [目标卡：减脂 40% / 倒计时 18 天]               |
| [目标卡：攒应急金 55% / 本周检查点]             |
|                                                  |
| AI 快速入口                                      |
| 输入一句话，帮我拆成目标与行动                   |
| [开始拆解]                                       |
+--------------------------------------------------+
```

#### 状态表

| 状态 | 页面表现 |
| --- | --- |
| 无目标 | 强引导创建目标，不直接落到空任务列表 |
| 目标为空但有任务 | 显示“这些任务尚未关联目标” |
| 行动视图 | 沿用任务筛选，但层级低于目标视图 |
| 逾期较多 | 顶部显示风险提示并提供重排入口 |

#### 设计验收点

- 切到 `行动` 时仍保留目标上下文。
- 目标卡必须能一眼看出“这个目标今天是否需要我行动”。

### 6.5 P05 Goal Detail

#### 业务目标

- 让目标详情承担“执行中心”的职责，而不是资料页。
- 承接目标基本信息、进度追踪、关联任务、提醒、倒计时和 AI 增强动作。

#### 推荐信息结构

1. 目标摘要卡
2. 进度追踪与关键结果
3. 今日关联任务
4. 提醒与倒计时
5. AI 工具：增强目标、补任务、查看规划记录

#### 状态表

| 状态 | 页面表现 |
| --- | --- |
| 新创建目标 | 鼓励立即生成任务与提醒 |
| 有规划记录 | 展示上次 AI 规划时间和入口 |
| 已完成目标 | 页头切换为完成态，弱化新增任务入口 |
| 已归档 | 只读模式，提供恢复入口 |

### 6.6 P06 Goal Breakdown

#### 业务目标

- 把当前多阶段 AI 流程做成统一、可信、可编辑的向导。
- 支持从新建目标、增强目标和新手引导进入同一条主流程。

#### 推荐步骤

1. 目标理解
2. AI 追问
3. 进度设计
4. 行动方案
5. 采纳落地

#### 低保真线框

```text
+-----------------------------------------------+
| < AI 目标规划                 步骤 3/5         |
| [阶段轨道：理解-追问-进度-行动-落地]          |
|                                               |
| 正在设计进度追踪                               |
| 系统会结合你的背景、时间和限制生成合理方案。   |
| [进度条 68%]                                  |
|                                               |
| 结果区 / 编辑区                               |
| [进度追踪卡]                                  |
| [修改按钮]                                    |
|                                               |
| [上一步] [继续生成行动方案]                   |
+-----------------------------------------------+
```

#### Goal Breakdown 状态表

| 状态 | 页面表现 | 备注 |
| --- | --- | --- |
| loading | 全屏步骤骨架 + 当前阶段文案 | 不要只显示菊花 |
| clarifying | 问题卡片 + 输入组件 | 支持暂存 |
| progress | 追踪方案结果 + 编辑入口 | 可删改 track |
| actions | 任务、提醒、倒计时分区展示 | 支持局部编辑 |
| applying | 明确告知正在保存到本地 | 强提示不可重复点击 |
| done | 成功态 + 自动跳转目标详情 | 顶部保留“已创建”提示 |
| error | 当前阶段错误 + 重试 | 不丢失已填写内容 |

#### 设计验收点

- 每一步都能说清用户现在在哪一步、下一步是什么。
- 任一阶段失败后，用户不会丢失已填写内容。
- 从 Onboarding 进入时，视觉可以更轻，但流程与正式版一致。

### 6.7 P07 Calendar

#### 业务目标

- 成为提醒、倒计时、任务落点的时间视图。
- 不重复承担 Today 的执行总控职责。

#### 信息结构

- 月/周切换
- 当前日期焦点
- 当日提醒
- 当日任务
- 倒计时

#### 状态表

| 状态 | 页面表现 |
| --- | --- |
| 日程为空 | 给出“创建提醒/添加倒计时”入口 |
| 任务多 | 当日卡片按时间/风险排序 |
| 仅有习惯提醒 | 展示连续打卡信息 |

### 6.8 P08 Voice Create Overlay

#### 业务目标

- 提升产品感知和创建效率。
- 让用户理解语音不是“录音机”，而是“快速创建助手”。

#### 四阶段交互

1. 等待输入：提示可语音可文本
2. 录音中：实时转写
3. 分析中：识别意图
4. 识别完成：告诉用户会创建成什么


#### 状态表

| 状态 | 页面表现 |
| --- | --- |
| idle | 引导语 + 文本输入框 + 常用示例 |
| recording | 红色录音态 + 实时文本 |
| analyzing | 进度态 + 文案说明 |

#### 业务目标

- 新手引导只负责降低理解成本，不再维护单独的功能链路。

## 7. 全局状态表

下表用于补齐设计稿中最容易遗漏的状态。

| 模块 | 必做状态 | 表现要求 |
| --- | --- | --- |
| 页面级 | loading / empty / error / offline | 不允许只有 toast |
| AI 能力 | checking / generating / preview / adopted / failed | 要有步骤感 |
| 同步 | idle / syncing / success / failed | 至少首页和 Me 可见 |
| 配额 | enough / low / exhausted | 要能跳会员页 |
| 会员 | guest / basic / premium / expired | 文案和 CTA 不同 |
| 公告 | none / active / dismissed | 关闭后当日不再频繁出现 |
| 语音 | idle / recording / analyzing / parsed / failed | 不允许只剩一段文字 |

## 8. 设计交付要求

设计稿至少需要覆盖以下内容：

- 浅色模式与深色模式
- 正常态、空状态、错误态
- AI 生成中和结果预览态
- 基础会员与高级会员差异态
- 同步成功与同步失败态
- 公告有/无两种态

设计稿至少需要同时覆盖以下页面的双模式版本：

- Today 首页
- 今日计划面板
- 一键重排面板
- Goals Hub
- Goal Breakdown
- Me
- Membership Center
- Voice Create Overlay

组件级设计稿至少需要给出以下双模式规范：

- 底部 Tab
- 按钮
- 卡片
- Chip / Badge
- 输入框
- 空状态
- 错误状态
- 公告 Banner
- 同步状态条

设计标注至少需要包含：

- 页面间跳转关系
- 每个 CTA 的点击后行为
- 加载时机
- 禁用态条件
- 超长标题、超长摘要、多任务、多提醒时的换行与截断规则
- 深浅色模式下的 token 映射关系

## 9. 设计验收清单

### 9.1 产品验收

- Today 是否足够像唯一首页。
- Goals 是否强化了目标驱动，而不是另一个任务列表。
- AI 功能是否共享统一交互模型。
- 会员、积分、配额是否已经形成一个完整认知闭环。

### 9.2 视觉验收

- 首页是否只有一个最强 Hero。
- 蓝、金、红三类语义色是否清晰区分。
- 卡片层级和留白是否一致。
- 暗色模式是否仍保持信息层级清晰。
- 深色模式下的底栏、图标、描边、弱文字是否仍有足够对比。
- 同一组件在浅色和深色模式下是否保持一致的语义和层级，而不是变成两套风格。

### 9.3 交互验收

- 所有 AI 流程都有生成中和失败态。
- 所有高价值动作都有明确结果反馈。
- 所有重要状态都不只靠 toast。

### 9.4 测试验收

- 新用户首次进入能否完成从引导到目标创建到回首页的完整链路。
- 已登录用户能否完成今日计划查看、采纳、编辑。
- 配额不足时是否总能被正确引导到会员页。
- 公告是否能正确展示、关闭、跳转。
- 积分流水能否正确解释扣费原因。
- 浅色模式和深色模式下，上述关键链路是否都能完成且无明显视觉断层。
