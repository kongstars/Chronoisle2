## 1. 文档目标

这份文档用于把新的 UI 风格直接落到四个一级页首屏。目标不是重写功能，而是明确：

- 页面第一屏应该长什么样
- 哪些信息必须先出现
- 哪些区域应折叠或弱化
- 模块高度和结构应该如何收敛

## 2. 全局首屏规则

所有一级页共同遵守：

- 页面左右边距统一 `16`
- 标题区尽量压在 `56-76`
- 搜索、筛选、模式切换等控制条优先紧凑
- 主操作必须在首屏出现
- 不允许首屏只看到大标题和装饰卡

## 3. Today

### 3.1 页面职责

- 告诉用户今天先做什么
- 提供立即可执行的任务入口
- 展示今日提醒和关键风险
- 让用户能直接开始、勾选、查看详情、重新规划

### 3.4 模块高度控制

| 模块 | 建议高度 |
| --- | --- |
| 问候区 | `60-76` |
| 搜索框 | `40-44` |
| 提醒卡 | `76-88` |
| 今日计划空态 Hero | `220-260` |
| 今日计划已采纳态 | `280-360` |
| 目标卡 | `180-220` |

### 3.5 设计要点

- Today 只能有一个主焦点，即 `今日计划`。
- 提醒卡横向滚动，但单张卡不要过窄。
- 目标区默认只显示 3 张，超出折叠。
- FAB 不能压住 Hero 的主按钮。
- 已完成任务保留并下沉，不隐藏。

## 4. 行动

### 4.1 页面职责

- 承担任务工作台角色
- 提供快速筛选、重排、定位和进入详情
- 允许用户在目标上下文中看见任务，而不是脱离目标地堆任务

### 4.2 首屏结构

```text
┌────────────────────────────────────┐
│ 我的目标与行动                 搜索 │
├────────────────────────────────────┤
│ [目标] [行动]                       │
```

### 4.3 模块高度控制

| 模块 | 建议高度 |
| --- | --- |
| 页头 | `56-68` |
| Segment | `32-36` |
| 筛选行 | `32-36` |
| AI 提示条 | `52-64` |
| 任务行 | `60-72` |

### 4.4 设计要点

- 行动页是列表优先，不要再做大 Hero。
- AI 重排入口保留，但视觉上应弱于主列表。
- 任务行右侧状态优先单列，不要三行堆叠。
- 切到 `目标` 时，目标卡优先展示“今天相关动作数”。

## 5. 日历

### 5.1 页面职责

- 提供时间结构视图
- 呈现当日提醒、倒计时、计划落点
- 成为提醒和日程的时间面板，而不是第二个任务首页

### 5.3 模块高度控制

| 模块 | 建议高度 |
| --- | --- |
| 页头 | `56-68` |
| 周/月切换 | `32-36` |
| 日历网格 | `220-280` |

### 5.4 设计要点

- 日期格优先结构清晰，不做重装饰。
- 选中日期用轻背景 + 主色边界，不用大面积实色。
- 提醒卡与 Today 保持同款结构。
- 时间型信息优先左对齐，不要散落。

## 6. 我的

### 6.1 页面职责

- 展示账户信息
- 提供会员、积分、同步、主题、设置等控制入口
- 作为系统与权益中心，而不是生活方式主页

### 6.2 首屏结构

```text
├────────────────────────────────────┤
```

### 6.3 模块高度控制

| 模块 | 建议高度 |
| --- | --- |
| 顶部说明区 | `56-72` |
| 用户摘要卡 | `96-120` |
| 会员权益卡 | `140-180` |
| 系统面板行 | `52-60` |

### 6.4 设计要点

- 模块更像控制面板，不像个人主页。
- 会员卡允许更强层次，但仍然要克制。
- 每一行都应明确是查看、跳转还是动作。
- 不要把所有入口都做成独立大卡。

## 7. 统一状态样式

### 7.1 loading

- 优先用结构占位，不用大面积动画
- 保留页面骨架，不整页切空

### 7.2 empty

- 文案短
- 给明确下一步动作
- 不用大插图

### 7.3 error

- 先说明失败原因，再给重试入口
- 风险色只在标题或按钮上小面积出现

### 7.4 completed

- 保留内容
- 降权显示
- 排序靠后

## 8. 设计交付要求

四个一级页的设计稿必须提供：

- 浅色模式
- 深色模式
- 首屏正常态
- 至少 1 个异常态或空态
- 模块高度标注
- 截断规则

如果设计稿只给大概样式，不给模块高度和截断规则，视为不可开发。

## 9. 前端落地要求

- 一级页必须优先复用同一套搜索框、提醒卡、任务行、目标卡、Hero 卡。
- 一级页不能各自重写一套 Today 风格、Calendar 风格、Me 风格的卡片体系。
- 页面主视觉必须先对齐模块高度和层级，再调颜色和边框。

## 10. 验收清单

满足以下条件才算通过：

- Today 首屏能同时看到搜索、提醒、今日计划
- 行动页首屏主要是列表而不是展示块
- 日历页首屏能同时看到日期结构和当天安排
- 我的页首屏像系统中心而不是内容流
- 四个一级页看起来像同一个产品，而不是四套视觉语言
