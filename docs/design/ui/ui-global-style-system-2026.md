## 1. 本轮目标

本轮不是简单换色或压缩高度，而是重新建立一套全局 UI 判断标准：让页面更美观，让信息更容易扫读，让内容呈现更有结构。

要解决的问题：

- 页面卡片很多，但每张卡片内部结构不稳定。
- 同类信息在不同页面的排列方式不一致。
- 视觉层次偏散，用户需要多看几眼才知道重点在哪里。
- 有些模块为了“显眼”使用了过重边框、过大圆角或过大留白。
- 深色和浅色虽然可用，但局部层级仍可能不一致。

本轮最终标准：

- 首屏必须能明确回答“今天要看什么、先做什么、异常在哪里”。
- 页面必须有清晰的信息骨架，而不是连续堆叠卡片。
- 美观来自比例、秩序、细节和一致性，不来自大色块和装饰。
- 所有页面都要保持效率工具的密度，避免运营页、管理页或社交产品式的松散表达。

## 2. 产品视觉定位

Chronoisle 的主端气质定义为：

- `清晰`：用户能快速识别模块、重点、状态和操作。
- `克制`：少用装饰，少用强色，少用厚重视觉。
- `精致`：依靠对齐、比例、细边框、轻阴影和准确排版建立品质。
- `结构化`：每个模块都有固定的信息语法，用户看熟后能快速扫读。
- `轻科技`：体现系统感、智能感和可靠感，不做炫技界面。
- `执行导向`：任何视觉表达都要服务任务判断和下一步行动。

一句话描述：

Chronoisle 应该像一张安静、精密、可执行的个人任务控制台，而不是一组漂亮但松散的信息卡片。

## 3. 全局信息结构

### 3.1 页面三层结构

每个页面必须按三层组织内容。

| 层级 | 名称 | 作用 | 典型内容 |
| --- | --- | --- | --- |
| L1 | 决策层 | 告诉用户当前页面最重要的判断 | 今日计划、会员状态、重排结果、目标进度 |
| L2 | 工作层 | 承载主要列表、表单和操作 | 任务列表、目标卡、提醒列表、积分流水 |
| L3 | 解释层 | 补充原因、规则、明细和风险 | AI 理由、同步说明、额度解释、错误信息 |

页面规则：

- L1 只能有一个主焦点，最多一个辅助焦点。
- L2 可以有多个模块，但每个模块必须能被标题和数量快速识别。
- L3 默认弱化，只有在用户需要理解原因时才展开或进入详情。

### 3.2 模块标题语法

所有分区标题统一使用“标题 + 数量/状态 + 操作”的结构。

标准格式：

```text
标题                         操作
数量 / 状态 / 时间
```

示例：

```text
今日提醒                      查看全部
4 条

正在推进的目标                查看全部
13 个

积压预览
预览 6 / 全部 142
```

规则：

- 标题必须说明内容类型，不使用抽象文案。
- 副标题优先放数量、状态、时间，不放长解释。
- 右侧操作只保留一个最重要入口。
- 如果模块没有操作，不保留空白占位。

### 3.3 卡片内容语法

所有信息卡片统一按四段组织。

| 段落 | 作用 | 展示要求 |
| --- | --- | --- |
| 识别 | 这是什么 | 标题、类型、状态标签 |
| 判断 | 当前情况如何 | 进度、数量、日期、风险 |
| 内容 | 有哪些具体项 | 任务、KR、提醒、流水 |
| 操作 | 用户能做什么 | 主操作、次操作、进入详情 |

禁止把解释文案放在识别段里，也禁止把多个操作挤进内容段。

### 3.4 数字展示规则

数字必须服务判断，不做装饰。

推荐格式：

- `13 个`：模块数量。
- `6/141`：处理进度。
- `20%`：目标或计划进度。
- `4 天后`：倒计时。
- `预计 6.5h`：计划负荷。

规则：

- 一个卡片最多保留一个最大数字。
- 同一行不要同时出现两个强数字。
- 数字右侧必须有语义标签，避免用户猜含义。
- 风险数字使用风险色，普通数量使用文本色或主色。

## 4. 页面骨架规范

### 4.1 Today 首页

目标：5 秒内让用户知道今天先做什么、有哪些风险、有哪些提醒。

页面顺序：

1. 顶部问候：问候语 + 日期星期 + 关键倒计时。
2. 搜索入口：单行搜索，不放说明文案。
3. 今日提醒：横向紧凑卡，最多露出 2.2 张。
4. 今日计划：唯一主 Hero，展示计划或生成入口。
5. 正在推进的目标：默认 3 张以内，更多进入独立页。
6. 其他辅助模块：只在有明确价值时出现。

今日首页禁忌：

- 不在问候下放长解释。
- 不把所有目标展开在首页。
- 不让今日计划卡长期占据半屏以上。
- 不用大面积主色强调非关键模块。

### 4.2 Task / Action 页

目标：高密度筛选和处理行动。

页面结构：

- 顶部：搜索、筛选、视图切换。
- 快捷状态：全部、今日、逾期、重点、已完成。
- 列表：按状态或时间分组。
- 批量入口：只在选择态出现。

任务列表规则：

- 一行优先展示标题、状态、日期、目标归属。
- 次级信息最多两条。
- 完成任务降权显示，不直接从上下文消失。
- 逾期和冲突必须有稳定的风险标识。

### 4.3 Calendar / Check-in 页

目标：让用户按时间理解提醒、打卡和倒计时。

页面结构：

- 顶部：月/周/日切换，当前日期明确。
- 日历区：只展示必要状态点，不塞长文本。
- 当日列表：使用和首页一致的提醒卡/任务行语法。
- 创建入口：保留全局 FAB，不重复造强按钮。

规则：

- 日历页风格必须和 Today 保持同一套卡片、字体、边框。
- 日期格只承担定位，不承担内容阅读。
- 当日内容才是主要信息载体。

### 4.4 Me 页

目标：账号、权益、数据和设置清楚分组。

页面结构：

1. 账户：头像、昵称、ID、会员短状态。
2. 权益：会员状态、积分余额、额度说明。
3. 数据中心：统计、积分流水、归档内容。
4. 系统设置：同步、主题、公告、帮助。

规则：

- Me 页不使用强烈黑金卡作为默认大面积视觉。
- 会员卡可以更精致，但不能破坏整体密度。
- 设置项统一列表行，不每个入口都做独立卡片。

### 4.5 AI 功能页

适用：今日计划、目标规划、一键重排、语音创建。

AI 交互统一四态：

| 状态 | 页面表达 |
| --- | --- |
| 可触发 | 说明输入和消耗，主按钮明确 |
| 生成中 | 真实阶段、真实进度或明确不可细分的阶段 |
| 结果预览 | 给结论、理由、影响范围 |
| 已采纳 | 显示已落地内容和可撤回/编辑入口 |

规则：

- 不展示假进度。
- 不用“AI 正在思考”这类空泛文案作为唯一反馈。
- 结果必须能被用户局部理解，不只给一段总结。
- 采纳前后视觉状态必须明显不同。

## 5. 视觉系统

### 5.1 颜色

色彩比例：

- `75%` 中性色和表面色。
- `15%` 主色和弱主色。
- `7%` 状态色。
- `3%` 会员、公告、特殊强调。

浅色模式：

- 背景：冷灰蓝，不使用纯白铺底。
- 卡片：白色或近白，边框非常轻。
- 主色：只用于选中态、主按钮、系统建议。
- 风险色：只用于逾期、失败、冲突。

深色模式：

- 背景：深蓝黑或冷灰黑。
- 卡片：比背景亮一档，避免纯黑。
- 边框：用低透明浅色，保证边界但不刺眼。
- 主色：亮度提高，面积降低。

禁忌：

- 同屏过多彩色标签。
- 大面积蓝底、绿底、红底。
- 深色模式下所有卡片一样亮。
- 会员金色侵入普通功能状态。

### 5.2 字体

字号基线：

| 语义 | 数值 | 场景 |
| --- | --- | --- |
| 页面标题 | 22 | 一级页面主标题 |
| Hero 标题 | 18 | 今日计划、会员主卡 |
| 分区标题 | 16 | 模块标题 |
| 列表标题 | 14 | 任务、提醒、目标明细 |
| 辅助信息 | 12 | 日期、状态、说明 |
| 标签 | 11 | badge、chip |

规则：

- 页面标题不超过 22。
- 卡片标题优先 14-16。
- 副信息统一 12，不能用 14 撑清晰度。
- 一屏内不要出现太多 Bold。

### 5.3 间距

全局间距：

| 语义 | 数值 |
| --- | --- |
| 页面左右边距 | 16 |
| 分区间距 | 14-16 |
| 卡片间距 | 10-12 |
| 卡片内边距 | 10-14 |
| 标题到副标题 | 4-6 |
| 列表行内部 | 6-8 |

判断标准：

- 高频页面优先更紧凑。
- 表单页面可以稍微放松，但不能超过 20 的常规间距。
- 如果某个模块靠大留白才显得“高级”，说明结构还不够清楚。

### 5.4 圆角与边框

圆角基线：

- 输入框、chip：10-12。
- 标准卡片：12-14。
- Hero 卡：16-18。
- 底部弹层：18-20。
- FAB：圆形。

边框基线：

- 普通卡片：1px 弱边框。
- 激活卡片：1px 主色或状态色边框。
- 危险卡片：弱红背景 + 细红边，不使用粗红框。

规则：

- 不使用 2px 以上大面积描边。
- 不使用满屏大圆角胶囊。
- 同一屏最多 3 个圆角等级。

### 5.5 阴影与层次

层次优先级：

1. 背景。
2. 普通内容卡。
3. Raised 卡和 Hero。
4. FAB、弹层、浮层。

规则：

- 普通卡片阴影应接近不可见。
- 只有浮层和 FAB 可以明显投影。
- 深色模式优先靠色阶和边框，不靠重阴影。

## 6. 组件规范

### 6.1 AppPanelSection

用途：页面分区，不是卡片。

要求：

- 只负责标题、副标题、右侧操作和内容承接。
- 不给整个 section 加背景卡。
- 内容间距默认 12-16。

### 6.2 AppCard

用途：承载独立信息对象。

标准结构：

```text
Row/Column
├─ Header: 标题 / 状态 / 数字
├─ Body: 1-3 条结构化内容
└─ Action: 可选，仅保留主要操作
```

规则：

- 卡片内部不再嵌套卡片。
- 卡片内说明文案最多 2 行。
- 卡片右上角只放一个状态或数字。
- 可点击卡片必须有明确进入详情的语义。

### 6.3 AppHeroPanel

用途：单页主决策模块。

使用条件：

- Today 今日计划。
- 会员权益主状态。
- AI 结果主摘要。
- 专注进行中。

规则：

- 单屏最多一个 Hero。
- Hero 内最多两个按钮。
- 描述文案最多 50 字。
- 已采纳态优先展示内容列表，空态优先展示决策入口。

### 6.4 AppTaskRow

用途：任务、计划、重排结果中的行动项。

结构：

- 左侧：完成状态或类型图标。
- 中间：标题 + 1 行 meta。
- 右侧：日期、风险、进入图标或状态。

规则：

- 标题最多 2 行。
- meta 最多 1 行。
- 完成后排序到末尾，保留可见。

### 6.5 AppGoalCard

用途：目标进展摘要。

结构：

- 顶部：类型标签 + 进度百分比。
- 中部：目标标题 + 今日行动数。
- 下部：最多 3 个 KR。

规则：

- 首页最多显示 3 张。
- 多余目标进入独立页面。
- 不把目标卡高度撑到接近半屏。
- 不同目标类型必须有明显但克制的区分：细色条、标签色、微弱背景，不用整卡大色块。

### 6.6 AppReminderCard

用途：首页和日历页提醒摘要。

结构：

- 左侧细状态条。
- 主标题最多 2 行。
- 一行状态或关联信息。

规则：

- 首页和日历页必须使用同一套提醒卡。
- 同一横向列表里的提醒卡高度必须一致。
- 默认置顶内容，不让底部留白破坏观感。

### 6.7 Bottom Navigation

结构：

- 四个固定 Tab：今日、任务、打卡、我的。
- 中间 FAB：上下居中，不能超出 tab 模块下沿。
- 底部安全区背景和 tab 背景一致。

规则：

- Tab 图标保持线性细节，不做重填充。
- FAB 是全局创建入口，不因切换 tab 消失。
- 选中态只用主色和字重，不额外增加大背景。

## 7. 信息展示模式

### 7.1 列表型信息

适用：任务、提醒、流水、公告。

模式：

```text
标题
主要 meta · 状态 meta
右侧状态 / 时间 / 金额
```

规则：

- 标题承载对象名称。
- meta 只放判断需要的信息。
- 右侧不放长文案。

### 7.2 进度型信息

适用：目标、计划、AI 进度。

模式：

```text
对象名称                 进度数字
当前状态
[进度条或 1-3 条明细]
```

规则：

- 进度数字必须有清楚口径。
- 进度条只在能帮助判断时出现。
- 不用多个进度条堆叠。

### 7.3 风险型信息

适用：逾期、额度不足、同步失败、AI 失败。

模式：

```text
风险标题
影响范围 / 原因
主操作
```

规则：

- 风险色小面积使用。
- 先说影响，再说原因。
- 必须给出可执行入口。

### 7.4 AI 结果型信息

适用：今日计划、一键重排、目标拆解。

模式：

```text
结果摘要
影响范围
分组建议
采纳 / 编辑 / 放弃
```

规则：

- 结果必须分组，不给长段落。
- 每个建议必须有理由。
- 涉及删除、延期、扣费的结果必须二次确认。

## 8. 深浅色模式

每个组件必须同时检查浅色和深色。

检查点：

- 背景与卡片边界是否清晰。
- 主色按钮是否仍有足够对比。
- 弱边框是否可见但不抢眼。
- 完成、失败、逾期、会员状态是否能区分。
- Tab 图标激活态和未激活态是否清楚。
- AI 模块是否不会在深色模式下过亮。

深色模式禁忌：

- 直接把浅色阴影复制到深色。
- 所有卡片使用同一深色。
- 弱文本过暗导致不可读。
- 主色面积过大导致刺眼。

## 9. 动效与反馈

动效只服务状态变化。

允许：

- 页面进入时轻微淡入。
- 列表刷新时保持位置稳定。
- 按钮点击时轻微缩放或明暗变化。
- AI 生成中使用真实阶段和轻量 loading。

禁止：

- 大范围弹跳。
- 大量卡片依次飞入。
- 无意义循环动画。
- 导致布局位移的加载动画。

## 10. 文案规则

文案要短、具体、可判断。

推荐：

- `今天还有 6 件行动`
- `已逾期 3 天`
- `预览 6/142`
- `AI 正在解析建议`
- `会员不限次数`

避免：

- `现在更适合先处理关键任务`
- `AI 将帮助你更好地安排今天`
- `这里可以查看你的数据中心`
- `这些是当前最重要的内容`

规则：

- 首页说明文案尽量不超过 20 字。
- AI 描述不超过 50 字。
- 按钮文案 2-5 字优先。
- 错误文案必须包含下一步。

## 11. 页面验收清单

每个页面交付前必须通过以下检查。

结构：

- 是否有明确 L1 主焦点。
- 分区标题是否有数量或状态。
- 同类信息是否使用同一组件语法。
- 是否移除了无意义长说明。

视觉：

- 是否没有大面积高饱和色块。
- 卡片高度是否贴近内容。
- 边框是否偏细。
- 圆角是否统一。
- 阴影是否克制。

密度：

- 首屏是否展示足够有效信息。
- 是否存在大块空白。
- 列表行是否可以快速扫读。
- 任务和目标是否没有被过度放大。

状态：

- loading、empty、error 是否都有设计。
- AI 生成中是否有真实状态。
- 失败是否有可执行下一步。
- 深浅色是否都可读。

交互：

- 可点击区域是否符合预期。
- 主操作是否唯一且明确。
- 危险操作是否二次确认。
- 切换 tab 后 FAB 是否保持稳定。

## 12. 改造顺序

建议按以下顺序落地，避免全局同时变动导致回归难排查。

1. 统一基础 token：颜色、间距、圆角、边框、阴影、字体。
2. 稳定共享组件：`AppPanelSection`、`AppCard`、`AppHeroPanel`、`AppTaskRow`、`AppGoalCard`、`AppReminderCard`、`AppSearchBar`。
3. 重做 Today 首页结构：先保证首屏信息质量。
4. 对齐 Calendar 和 Task 页：复用首页的提醒、任务、分区语法。
5. 对齐 Me 页：账户、权益、数据、设置四段式。
6. 对齐 AI 页：生成中、结果预览、采纳后状态统一。
7. 全量深浅色走查。
8. 真机检查底部导航、安全区、长文本、超长列表。

## 13. 一票否决项

出现以下任意问题，视为不符合本轮规范：

- 页面主要信息需要滚动很久才能看到。
- 卡片高度明显超过内容需要。
- 同类提醒卡在首页和日历页长相不同。
- AI 进度使用前端假进度。
- 深色模式下文字或边框不可读。
- FAB 在某个 tab 消失或超出底部模块。
- 使用大面积蓝色、红色、金色作为普通模块背景。
- 目标、任务、提醒、流水等列表缺少数量或状态口径。
