## 1. 当前工程概况

项目由 HarmonyOS ArkUI/ArkTS 客户端和 Node.js/Express/MongoDB 服务端组成。

主要目录：

- `entry/src/main/ets/pages`：客户端页面。
- `entry/src/main/ets/components`：客户端业务组件。
- `entry/src/main/ets/ui/base`：客户端基础 UI 组件。
- `entry/src/main/ets/services`：客户端服务封装。
- `entry/src/main/ets/widget`：HarmonyOS Form 桌面卡片。
- `server/routes`：服务端 API 路由。
- `server/services`：服务端业务服务。
- `server/models`：MongoDB 数据模型。
- `server/tests`：服务端回归样例和测试资产。
- `docs`：过程文档、产品文档、设计文档和恢复清单。

### 3.2 任务、提醒与打卡

客户端主要通过页面、服务和组件组合实现：

- 页面负责用户操作和状态展示。
- 服务层负责数据读写、接口调用和模型转换。
- 组件层负责任务行、状态徽章、日期聚合、筛选和操作按钮。

当前约束：

- 搜索页进入时保持空状态，只有真实关键词存在后才展示结果。
- 打卡页紧急程度颜色基于今天和 `Date.now()` 计算，不基于当前选中的日历日期。
- 打卡页负载等级保持 4 档语义：
  - `0`：灰色。
  - `1`：蓝色，1-4 条。
  - `2`：橙色，5-7 条。
  - `3`：红色，8 条及以上。

### 3.4 今日计划

今日计划当前分为三类来源：

- `local`：本地生成或本地修改的计划。
- `cloud_pending`：云端 AI 已生成但尚未采纳的计划。
- `cloud_adopted`：用户已采纳的云端计划。

客户端方案：

- `TodayPlan.ets` 定义 `TodayPlanSource`、`reason`、`adoptedAt`、`sourceGeneratedAt`、`planSource` 等字段。
- `TodayPlanService` 加载今日计划时同时处理本地计划、待采纳云端计划和已采纳云端计划。
- `TodayPlanPage` 支持查看待采纳计划、调整任务、采纳计划、展示原因和状态文案。
- `TodayTab` 只把非 `cloud_pending` 的计划视为已采纳计划，避免首页误展示未确认安排。

服务端方案：

- `server/routes/plan.js` 提供已采纳计划读取与保存接口。
- `server/services/PlanScheduler.js` 按上海时间凌晨调度生成计划。
- 调度逻辑会过滤待处理任务、去重周期提醒、保留今天/逾期已承诺任务，并要求 AI 输出任务原因和分组。
- 日期计算集中使用 `server/utils/date.js` 中的上海日期工具。

待补：

- 调度任务在真实账号和大量逾期任务下的稳定性验证。
- 待采纳计划编辑、采纳、放弃和重新生成的回归测试。
- 原因文案和分组解释继续产品化。

### 3.5 AI 重排

AI 重排由客户端重排页、服务端 Agent 路由和客户端应用服务组成。

近期调整：

- 客户端删除原弹窗组件，统一在重排页内完成预览和应用。
- 删除建议改为用户显式勾选后才应用，降低误删风险。
- 服务端 Prompt 要求所有逾期任务必须被完整覆盖，并且每个任务只能归入一个处理组。
- Prompt 增加跨目标同名任务约束，避免只按标题相似度删除不同目标下的任务。
- Prompt 增加自动周期提醒、依赖顺序、来源类型等约束。
- 客户端应用结果时会基于用户选择构造删除建议集合。

待补：

- 覆盖跨目标同名、自动周期提醒、依赖任务、删除选择的回归用例。
- 高风险建议的撤销、审计和二次确认体验。

### 3.6 语音创建

语音创建已从单一 `analyze` 流程扩展为分层链路。

客户端方案：

- `VoiceCreateOverlay` 负责录音、转写、确认文本、意图分类和路由。
- 弹层新增 `review` 阶段，用户可确认或编辑转写文本后再提交。
- `VoiceCreateService` 提供 `preClassify`、`classify`、`parseFields` 等方法。
- `VoiceCreateSession` 在页面间传递 `traceId`、原始文本、分析文本、意图、置信度和标题候选。
- 创建页通过 `AppAIFillBanner` 和 `AppAIFillIndicator` 展示 AI 字段填入状态。
- 任务、提醒、专注创建页已接入后台字段解析，并避免覆盖用户手动编辑字段。

服务端方案：

- `server/routes/voiceCreate.js` 提供 `POST /analyze`、`POST /classify`、`POST /parse`。
- 分类、解析、分析分别使用独立模型和超时配置：
  - `VOICE_CLASSIFY_MODEL`
  - `VOICE_PARSE_MODEL`
  - `VOICE_ANALYZE_TIMEOUT_MS`
  - `VOICE_CLASSIFY_TIMEOUT_MS`
  - `VOICE_PARSE_TIMEOUT_MS`
- 服务端生成和透传 `traceId`，日志中截断记录请求文本和模型输出。
- 字段解析缓存按用户、文本哈希和意图隔离，避免跨用户串数据。
- 标准错误返回包含 `errorCode` 和 `traceId`，用于前端降级和排查。
- `server/tests/fixtures/voice-create-cases.json` 已沉淀 10 个典型回归样例。

待补：

- 抽象统一 `AIFillState`，消除页面内重复状态。
- 将 fixtures 转成可执行自动化测试。
- 完善低置信度、空文本、改意图、字段冲突的交互策略。
- 真机验收录音、转写、跳转和字段填入。

### 3.7 华为 IAP 与自动续期

客户端方案：

- `AppConfig.getMembershipProductIds()` 集中提供会员商品 ID。
- `IAPService.queryProducts()` 使用华为自动续期商品类型查询会员商品。
- 购买完成后将 `jwsPurchaseOrder` 和 `productId` 提交到服务端校验。
- `MembershipPage` 使用配置化商品 ID 展示和发起购买。

服务端方案：

- `server/routes/iap.js` 提供：
  - `POST /api/iap/verifyOrder`
  - `POST /api/iap/huawei/notify`
- `server/services/HuaweiIapService.js` 负责：
  - 验证购买凭证。
  - 校验商品 ID。
  - 幂等记录订单。
  - 发放会员权益和积分。
  - 处理华为订阅通知。
- `IapOrder` 保存订单、权益发放、会员周期和原始交易信息。
- `IapEvent` 保存订阅通知、事件状态、人工复核标记和原始通知。
- `.env.example` 已补充华为 IAP 公钥、私钥、Key ID 和通知 URL 相关配置项。

待补：

- 华为沙盒月包、年包、续期、取消、退款、撤销、到期全链路验收。
- 通知签名、乱序通知、重复通知和人工复核状态验证。
- 生产密钥轮换和环境隔离方案。

### 3.8 会员、积分与权益

- IAP 订单发放会更新会员有效期，并按月度权益发放积分。
