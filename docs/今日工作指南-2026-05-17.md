## 任务 1（P0）— IAP 验证失败重试队列

**预计耗时**：2 小时 | **阻塞发布**：是（付费功能）

### 问题是什么

用户通过华为应用内支付（IAP）付了钱，但客户端调用服务器验证接口时网络抖动导致请求失败，服务器没收到验证请求 → 用户钱扣了但会员不到账。

### 需要做什么

在客户端 `IAPService.ets` 添加本地重试机制：验证失败时将订单存入本地持久化队列，按 3 个时间间隔自动重试（5分钟、30分钟、2小时），共 3 次。任意一次成功就从队列移除；3 次全失败则保留记录等待用户手动重试。

### 涉及文件

| 文件 | 作用 |
|------|------|
| `entry/src/main/ets/services/IAPService.ets` | IAP 服务入口，处理购买流程 |
| `entry/src/main/ets/models/IapOrder.ets` | 订单数据模型（可能已存在） |
| 可能需要新建 `entry/src/main/ets/services/IAPRetryQueue.ets` | 重试队列逻辑 |

### 操作步骤

#### 步骤 1：先阅读现有 IAPService

打开 `entry/src/main/ets/services/IAPService.ets`，找到购买全流程的关键方法。你需要理解：

- 购买请求发出后，华为 IAP SDK 返回什么
- 验证请求 `verifyPurchase()` 的调用链是什么
- 哪里可能抛出异常 / 网络失败

#### 步骤 2：设计重试队列数据结构

在客户端本地存储（使用 `@ohos.data.preferences` 持久化）中保存一个待重试订单数组：

```typescript
// 数据结构示意
interface PendingVerification {
  orderId: string          // 订单 ID
  purchaseToken: string    // 华为返回的购买凭证
  productId: string        // 商品 ID
  createdAt: number        // 首次失败时间戳
  retryCount: number       // 已重试次数（0/1/2）
  nextRetryAt: number      // 下次重试时间戳
  lastError: string        // 最后一次错误信息
}
```

- `retryCount` 在 0/1/2 时还会自动重试，第 3 次失败后停止
- 重试间隔：首次 5 分钟，第二次 30 分钟，第三次 2 小时

#### 步骤 3：实现重试队列服务

新建 `entry/src/main/ets/services/IAPRetryQueue.ets`，提供以下方法：

| 方法 | 功能 |
|------|------|
| `addToQueue(order)` | 验证失败时将订单加入队列 |
| `processQueue()` | 检查是否有到期重试的订单，逐个重试验证 |
| `removeFromQueue(orderId)` | 验证成功后移除 |
| `getPendingOrders()` | 获取所有待处理订单（用于 UI 展示） |

**调用时机**：
- `addToQueue()`：在 `verifyPurchase()` 的 `.catch()` 中调用
- `processQueue()`：App 启动时调用一次 + 每次 App 回到前台时调用一次

#### 步骤 4：修改 IAPService.ets

在现有的 `.catch()` 块中将失败订单加入重试队列：

```typescript
// 伪代码 — 找到现有 verifyPurchase 调用并在 catch 中添加
.catch((error) => {
  console.error('[IAP] verifyPurchase failed:', JSON.stringify(error));

  });

```

#### 步骤 5：在 EntryAbility 中注册生命周期触发

打开 `entry/src/main/ets/entryability/EntryAbility.ets`，找到 `onForeground()` 回调，添加 `IAPRetryQueue.processQueue()` 调用。

## 任务 2（P0）— CloudSync 认证失败保护

**预计耗时**：1 小时 | **阻塞发布**：是（数据安全）

### 问题是什么

`CloudSyncService.ets` 中的 `fetchCloudData()` 方法，当请求返回 401（认证失败/Token 过期）时，代码可能返回了空数组 `[]`。这个空数组随后会覆盖（merge）本地已有的数据，导致用户数据丢失。

### 需要做什么

区分 HTTP 错误类型：401/403 认证错误时直接抛出异常阻断合并流程，不让空数据污染本地。

### 涉及文件

| 文件 | 作用 |
|------|------|
| `entry/src/main/ets/services/CloudSyncService.ets` | 云端同步服务 |

### 操作步骤

#### 步骤 1：阅读 CloudSyncService

打开 `entry/src/main/ets/services/CloudSyncService.ets`，找到 `fetchCloudData()` 方法。

重点关注：
- HTTP 请求返回后的 `.then()` / `.catch()` 处理
- 返回值被谁调用（通常是 `syncData()` 或 `mergeData()` 方法）

#### 步骤 2：修改 fetchCloudData

在 HTTP 响应处理中，**先判断状态码**，再判断数据：

```typescript
// 伪代码 — 修改方案
fetchCloudData(): Promise<CloudData | null> {
  return httpRequest(url).then((response) => {
    // 成功 — 正常返回
    return response.data;
  }).catch((error) => {
    // 关键修改：区分错误类型
    if (error.code === 401 || error.code === 403) {
      // 认证失败 — 抛出异常阻断上游合并
      console.error('[CloudSync] Auth failed, abort sync. Code:', error.code);
      throw new Error('AUTH_FAILED');
    }
    // 其他网络错误 — 也抛出，不返回空数组
    console.error('[CloudSync] Network error:', JSON.stringify(error));
    throw error;
  });
}
```

**核心原则**：任何非 2xx 响应都不要返回空数组。要么抛出异常，要么返回 `null` 并由调用方判断。

#### 步骤 3：追溯调用方

在同一个文件中找到调用 `fetchCloudData()` 的地方（通常是 `pullFromCloud()` 或类似方法），确认：

- 如果收到 `AUTH_FAILED` 异常，不应执行数据合并
- 用户应收到轻提示"登录已过期，请重新登录"
- 本地数据不受影响

### 验证方式

1. 在服务端返回 401（可以用 Postman 先测），确认客户端不会清空本地数据
2. 确认控制台有 `[CloudSync] Auth failed` 日志

## 任务 3（P1）— 第三方登录 Promise 悬挂

**预计耗时**：30 分钟 | **阻塞发布**：是

### 问题是什么

`ThirdPartyLoginPage.ets` 中打开 WebView 进行第三方授权登录。如果用户中途返回（没有完成授权），WebView 被销毁，但 Promise 永远不会 resolve/reject，导致调用方永远在等待。

### 涉及文件

| 文件 | 作用 |
|------|------|
| `entry/src/main/ets/pages/ThirdPartyLoginPage.ets` | 第三方登录页面 |

### 操作步骤

#### 步骤 1：阅读文件

打开 `entry/src/main/ets/pages/ThirdPartyLoginPage.ets`，找到：
- 打开 WebView 的逻辑
- 返回的 Promise（可能是 `new Promise(...)` 或某个回调）

#### 步骤 2：找到 aboutToDisappear 生命周期

ArkTS 组件生命周期方法 `aboutToDisappear()` 在页面即将消失时被调用。

#### 步骤 3：在 aboutToDisappear 中添加清理逻辑

```typescript
// 伪代码
aboutToDisappear(): void {
  // 如果页面消失时 Promise 还未 resolve，说明用户取消了登录
  if (this.loginPromisePending) {
    this.loginResolver?.onError?.('cancelled'); // 或者 reject(new Error('LOGIN_CANCELLED'))
    this.loginPromisePending = false;
  }
}
```

**关键点**：
- 你需要先在类中添加一个 `loginPromisePending: boolean` 状态标记
- 在 Promise resolve 时将此标记设为 `false`
- 在 `aboutToDisappear` 中检查标记，如果仍为 `true` 则调用 reject

### 验证方式

1. 点击第三方登录按钮，在 WebView 加载时立即按返回键
2. 确认调用方（通常是 LoginPage）收到取消回调，不再显示 loading
3. 确认无内存泄漏（重复操作后内存不会持续增长）

## 常见问题

**Q: 我改完代码后怎么验证？**
A: 每次改完一个文件，先跑 `hvigorw assembleApp` 确认编译通过，再在模拟器/真机上验证功能。

**Q: 找不到某个文件怎么办？**
A: 用全局搜索（VS Code: Ctrl+Shift+F）搜文件名或类名。HarmonyOS 项目的目录结构可能有细微差异。

**Q: 不确定修改是否正确？**
A: 参考项目中已有类似功能的代码风格。例如：不确定按钮怎么写 → 看其他页面怎么用 AppButton。

**Q: 遇到编译错误怎么办？**
A: 优先确认是否缺少 `import` 语句。ArkTS 不会自动补全导入。

**Q: 某个任务卡住了怎么办？**
A: 先跳过做下一个，把所有能做的做完再回来。记录卡住的原因和日志，方便后续排查。
